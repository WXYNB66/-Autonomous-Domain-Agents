# TSagent：成果导向的自治专业智能体标准

> 本库记录 TSagent 截至 2026-07-24 的角色、会谈、工具与验收设计标准。它以 Eleanor（理财规划师）的当前自治实现为参考，不把旧的固定工作流或字段命中规则当作标准。

## 核心立场

专业智能体不是“把用户填进表单后跑流程”。它应当在每一轮：理解最新表达与更正、自己定义当前可完成的岗位目标、先交付阶段性价值，再判断是否需要工具或协作。信息不足、工具失败或技术延迟都不等于整场咨询失败。

```text
用户新表达 / 更正
→ 版本化会谈快照
→ 自然语言工作记忆
→ 角色租约与岗位主成果
→ 角色自主目标循环
→ 条件性成果 / 工具证据 / 协作 Brief
→ 安全审计与无损人格化交付
→ 提交下一个会谈版本
```

## 与早期流程设计的根本区别

| 早期错误做法 | 当前标准 |
|---|---|
| 根据字段是否齐全决定能否回答 | 先给已有事实支持的阶段成果，只问一个真正改变下一步的事实。 |
| 编排器每轮替角色决定专业动作 | 编排器只路由、恢复角色租约和管理会谈状态；专业判断由角色完成。 |
| 工具、JSON 或质量门不通过就发业务 fallback | 保留专业正文和已确认事实；只有真实技术不可用且没有任何安全成果时才提示维护。 |
| 人格化层摘要、挑重点或重做专业判断 | 人格化层无损润色已经批准的专业正文，不得删除结论、条件、数字和行动顺序。 |
| 三个模块各自读取权限 | 工具展示、Manifest、桥接和网关必须读取同一个授权事实。 |
| 一次角色失败关闭整场会议 | 写入技术连续性事件，保留会话、版本和已有成果，再由编排器决定恢复、等待或条件性交付。 |

## 当前参考实现：Eleanor

Eleanor 是理财规划师，不是产品推荐器。她负责把目标、期限、现金流、流动性、保障与风险边界整理成可执行的资金分桶、执行顺序和条件性方案。她可以：

- 在用户资料不完整时先画出决策边界与最小行动；
- 吸收用户最新更正，使旧前提失效；
- 判断静态计算或证据是否会改变本轮方案；
- 使用 `wealth.calculate` 类工具取得 Evidence Envelope；
- 在工具未成功时保留无工具的条件性成果；
- 将专业正文无损转化为自然、符合角色语气的回复。

她不负责风险放行、最终家庭资本裁决、外部事实编造或具体产品推介。

## 新角色上线前的最小门槛

1. 写清岗位独有成果、不能做什么、何时停止；
2. 能从自然语言工作记忆完成一次独立阶段交付；
3. 能吸收最新用户更正，且不被旧报告覆盖；
4. 工具只在结果会改变行动时选择；权限、Manifest、桥接、网关使用同一授权事实；
5. 安全审计不吞掉已有成果；人格化交付不摘要或改写业务含义；
6. 通过逐句真实用户会谈验收，报告必须保留用户与角色原文、工具审计和人工业务评分。

> 文档描述“标准”和“当前已实现能力”时必须分开标注；不要把规划中的会话级授权、工具成功率或角色能力写成已经上线的事实。
