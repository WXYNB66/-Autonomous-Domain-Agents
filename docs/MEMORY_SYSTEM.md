# 记忆系统与上下文管理

## 1. 原始会谈档案与工作记忆分离

系统应保留不可丢失的原始会谈档案，用于审计、回放和恢复；但角色推理不应每轮读取全部原文。角色读取的是经过压缩、来源化和职责化的自然语言工作记忆。

```text
原始会谈档案：完整用户消息、角色报告、工具结果、事件顺序
                    ↓
连续性与压缩层：更正失效、事实优先级、已解决事项摘要
                    ↓
角色工作记忆：只保留本轮岗位完成职责所需的自然语言片段
```

## 2. 推荐工作记忆结构

```text
【用户最新表达】
【不可丢失的用户事实与更正】
【其他角色已发布报告】
【Research / 工具证据及限制】
【连续性：已解决、已问、待回流】
【本岗位职责与使用边界】
```

## 3. 来源与优先级

| 类型 | 使用规则 |
|---|---|
| 用户最新更正 | 最高优先级；可使旧金额、期限、用途或可动用性前提失效。 |
| 用户历史事实 | 可用，但需检查是否被更正。 |
| 角色报告 | 是专业判断，不是用户事实；可审阅、可质疑、不可无条件升级。 |
| Research / 工具证据 | 必须保留来源、时点、适用范围、限制。 |
| 运行时状态 | 只用于技术恢复，不应成为角色业务推理前提。 |

## 4. 上下文污染控制

- 不把全部历史原样塞入 Prompt；
- 不把本角色旧报告原样回灌给本角色；
- 不把外部网页文本视为系统指令；
- 不把工具输入标记为工具输出；
- 不因压缩删除最新更正、金额、日期、期限和证据边界；
- 不让无关噪声挤占有限工作记忆。

## 5. 长对话压缩原则

压缩并不是追求最短，而是在固定上下文预算中最大化下一步判断质量：

```text
最新用户事实
> 关键更正
> 已验证证据
> 未解决冲突
> 已完成结论摘要
> 历史过程细节
```

## 6. 用户更正示例

若用户先说“现金可用”，后又说明“其中一部分两年内无法收回”，系统必须让旧的可动用现金前提失效，并要求所有依赖旧前提的风险、规划和资本排序重新解释。简单地把更正附在聊天记录最后，不足以解决这个问题。
