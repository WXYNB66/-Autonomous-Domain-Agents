# 安全、权限与交付边界

## 1. 规则治理技术，语义治理业务

规则可以管理身份、租户、速率、Schema、幂等、版本、预算、日志和工具权限；规则不能替角色决定谁该上场、是否追问、资金如何安排、风险是否放行或报告是否专业。

## 2. 安全门的唯一职责

安全门只处理：编造事实、伪造工具/来源、关键事实冲突、越权承诺、权限破坏、危险指令和真实技术异常。

安全门对可修复问题给出反馈目标，而不是把业务正文替换为模板。角色根据反馈更新目标、修复成果或交付已有安全阶段价值。人格化层不得重新做安全裁决。

## 3. 工具权限标准

工具授权必须至少有四个一致的面：

```text
角色可见能力
= Manifest 可见性
= 工具桥接 granted_scopes
= GatewayContext granted_scopes
```

开发环境可用全局配置做验收；生产环境必须使用会话级、目的级、可撤销授权。敏感财务资料、保单、受益人和身份资料必须单独记录同意范围、工具目的、输入来源和审计时间。

工具只接收显式、带来源输入；返回 Evidence Envelope；不读取角色私有状态；不输出产品推荐或最终裁决。

## 4. 技术失败与用户体验

技术失败不包含业务建议。若角色已有安全专业成果，应交付成果并把未完成部分说明为限制；若完全没有成果，才说明系统当前不可用并保留会谈。不得用 fallback 假装业务完成，也不得关闭长期咨询。

## 5. 金融边界

系统提供教育、规划、情景与证据整理，不承诺收益、不直接代客操作、不把条件性框架伪装成适当性或持牌建议。面对真实客户时还需要身份验证、租户隔离、加密、数据保留与删除、审计、人工复核和地区合规评估。
