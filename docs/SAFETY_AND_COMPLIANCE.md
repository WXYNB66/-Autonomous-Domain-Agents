# 安全、合规与系统边界

## 1. 不把专业判断写成规则引擎

TSagent 反对的是用关键词、字段完整度、固定角色顺序或静态目标树替代专业判断，而不是反对所有规则。

| 不应由规则决定的业务问题 | 应由规则治理的技术问题 |
|---|---|
| 哪位角色当前最有新增贡献 | 身份、权限、租户隔离 |
| 是否应追问、数据核验、协作或停止 | 输入 Schema、请求上限、预算 |
| 风险是否应升级、方案是否可推进 | 超时、重试、幂等、速率限制 |
| 工具结果是否改变岗位行动 | 审计、来源格式、失败关闭 |

核心原则是：**规则保护系统，语义层服务业务。**

## 2. 角色边界保护

每个角色必须公开自己的职责、证据责任和不负责事项。角色之间可以互相挑战，但不应借其他角色的报告越权给出最终结论。

- 规划角色不能替风险角色宣布风险已放行；
- 风险角色不能替用户决定目标偏好；
- 数据分析师不能把未经解释的网页内容升级为行动建议；
- 编排器不能替任何角色下专业判断；
- 工具不能输出未经角色解释的业务裁决。

## 3. 工具安全

工具服务应是独立、显式、可审计的能力：

- 只接收经过授权、带来源的显式输入；
- 使用最小权限、用户同意、范围限制和预算；
- 工具展示、Manifest、桥接和网关读取同一授权事实；
- 返回 Evidence Envelope，而不是最终建议；
- 对超时、无权限、参数无依据、数据源不可用明确失败语义；
- 不读取角色私有状态，不把工具输入伪装为工具证据。

## 4. 外部证据与提示注入

网页、搜索摘要、第三方数据与文档内容属于外部材料，不是系统指令。它们必须带来源、时点和适用范围，并且不能影响：

- 身份与权限；
- 工具 Scope 与用户同意；
- 模型配置与供应商路由；
- 系统提示词、运行预算或审计策略。

## 5. 用户数据与监管边界

财富管理数据具有高敏感性。生产系统应具备真实身份认证、租户隔离、加密、密钥管理、数据保留与删除策略、审计日志、访问控制、供应商数据处理说明和人工复核机制。

白皮书提出的是架构方法，不构成投资建议、产品推介、账户操作或自动化适当性结论。任何面向真实客户的部署都必须遵守适用地区的金融、隐私和消费者保护要求。

## 6. 技术连续性与非破坏性质量审计

当工具、模型、证据或上下文不能可靠支持结论时，系统必须：

1. 保留已验证事实与已完成的主成果；
2. 明确哪些部分不可判断以及原因；
3. 给出最小可推进动作；
4. 不用猜测、旧报告或错误参数伪造完整结论。

质量审计的职责是隔离危险行为，而不是把专业工作重新做成表单校验。它可以拦截伪造事实或来源、关键冲突、越权、未授权工具使用与安全破坏；但不得因信息尚未齐全、工具未调用、结构化字段缺失、投影格式异常或本轮目标未全部完成而吞掉已批准的阶段成果。

若存在安全业务成果，应保留原专业正文并如实说明边界；只有模型或基础设施真实不可用、且没有任何安全可交付内容时，才向用户发送不含业务判断的维护提示。开发期全局 Scope 不能等同于生产期用户授权；生产授权应可按会话、用途和范围撤销。
