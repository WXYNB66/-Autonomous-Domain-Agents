# 动态会谈协议

## 先理解这张图

会谈**不是没有流程**，而是流程不会预先写死“谁先说、谁后说”。每当出现用户消息、用户更正、角色报告或外部证据时，系统都根据当前未解决的业务问题动态决定：

- 现在是否有角色能创造新增专业价值？
- 如果有，应该由哪一位角色上场？
- 如果没有，是等待必要信息，还是保留会谈并在下一次补充时继续？

```mermaid
flowchart TD
    START([出现新事件\n用户消息 / 更正 / 报告 / 证据])
    START --> MEMORY[构造当前工作记忆\n保留最新用户事实、证据与未解决事项]
    MEMORY --> VALUE{是否存在\n新增专业价值？}

    VALUE -- 暂无 --> HOLD([保留会谈\n交付当前阶段成果，等待后续事件])
    VALUE -- 是 --> CHOOSE[编排器选择\n当前最合适的一位专业角色]
    CHOOSE --> ROLE[角色独立理解\n形成岗位主成果]

    ROLE --> NEED{完成主成果后\n还缺什么？}
    NEED -- 不缺 --> REPORT[发布自然语言报告\n+ 协作 Brief]
    NEED -- 用户独有事实 --> ASK[提出最小必要追问]
    NEED -- 外部事实 --> DATA[请求数据分析师核验 / 等待证据]
    NEED -- 其他专业判断 --> EXPERT[请求对应专家审查]
    NEED -- 工具结果会改变行动 --> TOOL[一次受控工具调用\n→ Evidence Envelope]

    ASK --> REPORT
    DATA --> REPORT
    EXPERT --> REPORT
    TOOL --> REPORT
    REPORT --> EVENT[发布为来源化协作事件]
    EVENT --> NEXT{是否有新的\n待解决业务问题？}
    NEXT -- 是 --> MEMORY
    NEXT -- 暂无 --> HOLD
```

## 1. 核心原则

> **不是角色按顺序开会，而是问题驱动角色上场。**

用户提出问题后，系统不预设“先金融顾问、再理财规划师、最后首席财务官”。当前最有价值的角色可能是风险分析师，也可能是数据分析师，甚至可能没有任何角色应该继续发言。

## 2. 编排器只做三类决定

| 决定 | 含义 | 典型结果 |
|---|---|---|
| `act` | 当前有一位角色能带来新增专业价值 | 调度该角色完成自己的主成果。 |
| `wait` | 关键事实只能由用户或尚未返回的外部证据提供 | 提出最小追问，或等待数据证据回流。 |
| `hold` | 当前继续发言不会带来新增价值 | 交付当前可用成果，保留会谈，等待用户、证据或恢复事件。 |

编排器不决定资产配置、不判断风险是否可接受，也不替角色写报告；它只负责协调“谁应该做下一步”。正在履行职责的角色拥有会谈租约：用户回答它的关键问题时，默认回到该角色；角色明确委托其他岗位时，编排器默认尊重该委托。若因技术执行原因无法照办，必须留下非业务裁决式的执行原因，而不能替角色否定专业判断。

## 3. 一次角色回合如何交付

每个角色输出两层自然语言内容：

```text
主成果（report_text）
- 本角色已经完成的专业判断、事实边界、条件和下一步价值。

协作 Brief（collaboration_brief）
- 只有确有必要时才说明：应由谁补什么，或为什么应停止。
```

这样，“请求别人继续”不会掩盖本角色已经完成的工作。

## 4. 什么时候允许追问用户

只有同时满足以下条件才追问：

1. 该事实只能由用户确认；
2. 当前上下文、角色报告和证据没有答案；
3. 不同答案会改变本轮成果或行动；
4. 无法通过条件性方案、数据核验、专家协作或保留会谈继续推进。

因此，信息不完整不等于立即追问；用户注意力是有限资源。

## 5. 为什么角色业务回合不完全并行

角色往往需要读取其他角色的新报告。例如规划师需要先理解风险边界，首席财务官需要理解规划方案和证据。因此，专业业务判断以事件顺序交接。

可并行的是前端进度推送、事件持久化、独立外部证据获取和后台技术任务。系统避免的是“编排器高频空转”，而不是为了并行让角色基于不同事实版本同时下结论。

## 6. 技术失败不等于会谈结束

一次角色、工具或模型调用的技术失败，只能形成一条**技术连续性事件**：说明本轮哪一段未完成、已保存哪些用户信息、哪些已批准成果仍可继续使用。它不是新的用户事实、角色结论或结束命令。

因此，恢复顺序是：保留已有阶段成果 → 标出未完成边界 → 由当前角色续做、条件性交付或等待必要信息。系统没有权利因为一次执行异常关闭长期咨询；“结束”只能是用户主动结束，或会谈已被明确归档的生命周期动作。
