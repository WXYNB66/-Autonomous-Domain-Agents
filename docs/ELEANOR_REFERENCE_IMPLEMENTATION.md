# Eleanor 当前参考实现与角色标准差距清单

> 更新时间：2026-07-24。本文不是愿景文档，而是以当前 TSagent 代码与真实验收为依据的参考实现说明。后续角色应复用其正确范式，同时不得继承未解决缺陷。

## 1. 已形成的参考范式

### 1.1 自治主路径

当前 `autonomous_primary` 下：

```text
EleanorAgent
→ EleanorAutonomousAgent
→ EleanorCombinedToolLoopHarness
→ 组合语义决策 / 工作集 / 工具闭环 / 交付层
```

旧的规划图路径仍可作为兼容代码存在，但不是新角色的设计起点。新角色必须先具有独立自然语言工作记忆入口与自治回合能力。

### 1.2 阶段成果而非表单追问

Eleanor 已能在用户只提供目标、期限和部分现金流时给出资金桶草图、条件边界和最小下一步；用户更正目标优先级后，能调整旧分桶前提。标准是“先给可逆价值，再问一个关键事实”，不是“字段齐全才回答”。

### 1.3 无损交付

`professional_detail` 是角色专业成果；人格化层的工作是无损润色。已实现的防线包括：不把候选角色回复错当用户话、两次润色仍明显压缩时回退到原专业正文、只有没有任何专业源时才给纯技术维护提示。

### 1.4 工具价值合同

Eleanor 的工具循环包含：工具候选、反事实授权、Manifest 就绪、参数编译、WPMT 网关、Evidence Envelope、证据解释。工具失败时应恢复条件性方案，不伪造结果。

## 2. 当前已发现的真实缺口

### 2.1 工具权限的单一事实来源

真实验收暴露过“展示层和 Manifest 看得到工具，桥接层看不到”的分裂。标准要求：

```text
settings / 会话授权事实
→ visibility
→ manifest grounding
→ bridge context
→ gateway context
```

桥接层已改为读取统一 `settings`；该改动必须在后端重启后用真实 Evidence Brief 成功样本复验，才可称工具执行稳定。

### 2.2 开发全局同意不是生产授权

当前开发验收可用 `ELEANOR_WPMT_SCOPES=wealth.calculate` 与敏感数据同意开关。生产标准仍未完全实现：授权应绑定会话、工具目的、数据类别和可撤销状态，而不是永久全局开启。

### 2.3 工具成功的定义

`tool_calls=1` 不等于成功。必须同时看到：

```text
tool_status = succeeded
Evidence Brief 非空
输入来源与限制可见
角色明确解释证据如何改变方案
```

### 2.4 编排角色匹配

真实前端会谈中，部分“资金桶 / 现金流”场景仍可能被 Warren 接管而非 Eleanor。后续应继续用岗位成果卡和角色租约约束编排；不能靠关键词路由，也不能为测角色而永久硬编码路径。

### 2.5 依赖健康

Qdrant 不健康、工具网关错误、模型尾延迟都必须被观测和区分。它们不应被误诊为角色能力差，也不应覆盖角色已经完成的安全成果。

## 3. 对其他角色的强制迁移要求

1. 采用自然语言工作记忆与最新更正优先；
2. 把岗位主成果和协作 Brief 分开；
3. 工具路径共享单一授权事实；
4. 安全审计只治理危险行为，交付层无损；
5. 技术失败产生连续性事件，不关闭会议；
6. 真实验收必须保存原文和工具全链路审计；
7. 任何“未实现”不得在角色介绍中写成已具备能力。

## 4. Eleanor 当前结论

- 语义理解、条件性规划、阶段成果与无损交付：已达到内测候选水平；
- 前端路由：可工作但仍需持续岗位匹配验收；
- 工具闭环：权限分裂已修复代码，等待重启后的真实网关成功样本；
- 正式上线：仍取决于会话级授权、工具成功率、依赖健康和多场真实会谈复验。
